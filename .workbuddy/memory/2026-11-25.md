## Bug 修复：棋子点击无响应 + 棋子文字

- 用户反馈：模拟器里棋子无法移动、棋盘显示不对。

- 验证：13 项规则测试 + 6 项 UI 测试 + 语法检查全部通过；打印初始布局核对无误（炮在 col1/7，卒兵在 col 0/2/4/6/8）。

## Bug 修复：走子高亮不显示（第二轮，根因定位）

- 用户提供开发者工具版本 2.01.2510290 win32-x64（这是工具版本，非基础库版本；工具很新，基本排除版本过旧）。
- 真正根因：组件用多字段联合 `observers: {'board, selected, hints, lastMove': ...}`，属较新基础库特性，若监听不触发则 lastMove 变化后不重新渲染。此前 Node 测试直接调 render 绕过了该机制，所以测试通过但真机无效。
- 修复 1：改用 properties 单字段 observer（每个属性 `observer: 'onPropChange'`），兼容性更好；加 `lifetimes.attached` 首屏渲染兜底。
- 修复 2：高亮改为独立置顶层 —— render 产出 `moveFromPoint`/`moveToPoint`（含 index/x/y），WXML 在棋子之后渲染两个 `.move-mark-layer`（z-index:10, pointer-events:none），起点红虚线圈 + 落点红色圆环，避免被棋子/交点层叠覆盖。
- 修复 3：高亮层加 `data-index` + `bindtap="onPointTap"` 转发点击，防止置顶层拦截导致落点棋子点不动（避免重蹈 Earlier 事件冲突覆辙）。
- 测试 mock 改为模拟 properties 写入 data 后触发 onPropChange；新增 attached 生命周期测试；断言改为检查独立层坐标。
- 验证：13 项规则 + 8 项 UI + 语法检查全通过。
- 教训：Node 直调 render 的测试会掩盖小程序 observer/生命周期机制问题；涉及组件渲染触发的 bug，必须让测试模拟真实的属性变更→observer 链路。

## 功能：平板棋盘自适应

- 问题：截图反馈 iPad Pro 上棋盘固定 360×399px，占屏很小。
- 方案：不改内部坐标体系（render 仍用 CELL=39/PAD=24 的固定像素布局），在组件外层包 `.board-scaler`，内部 `.board` 用 `transform:scale({{scale}});transform-origin:0 0` 整体缩放；所有棋子、线条、特效、横幅随之等比放大，点击命中区同步缩放。
- 尺寸计算：`_updateScale(size)` 取 `wx.getWindowInfo()`（回退 getSystemInfoSync / 默认值），可用宽 = windowWidth-32、可用高 = windowHeight-170（预留状态栏/按钮/提示），scale = min(可用宽/360, 可用高/399)，限制在 0.72~3.2；手机约 0.95 保持原大小，iPad 竖屏约 2.7 倍，横屏按高度约 2.1 倍。
- 监听 `wx.onWindowResize` 在 attached 注册、detached 解绑，横竖屏/分屏切换自动重算。
- 页面 `.status-bar` 和 `.board-wrap` 宽度由固定 360px 改为 100%，状态栏也随屏宽铺开。
- 测试坑：组件 mock 需把 `componentDef.methods` 全部绑到实例（attached 会调 this._updateScale），并给 data 默认 board/hints/selected，否则首屏渲染报错。新增 2 项测试（视口尺寸计算、缩放容器与监听解绑）。15 规则 + 34 UI + 语法 + WXML 标签配对检查全通过。
- 炮兵位角标：组件 render 新增 `markers`（4 炮位 row2/7 col1/7 + 10 兵卒位 row3/6 col0/2/4/6/8），WXML 在交点层之后、棋子层之前渲染 `.pos-mark`（四角各一个 L 形短线，颜色同棋盘线 #967446），`pointer-events: none` 不挡点击，随棋盘整体缩放。用户反馈后角标边长由 8px 缩到 6px（偏移 -13→-11，距交点仍 5px）。15 规则 + 36 UI + WXML 配对检查全通过。
- 棋子字体加粗：`components/chessboard/index.wxss` 中 `.piece`、`.captured-ghost`、`.drop-ghost` 的 font-weight 由 500 改为 bold（楚河汉界保持 500）。15 规则 + 35 UI 全通过。
- 后续修复：红方底行棋子压/超出棋盘边框。根因 `.board` 是 `box-sizing: border-box` + 5px 实体边框，绝对定位子元素相对边框内侧定位，外层高度只算了内容区 399px，导致底行比顶行低 10px。修复：`BASE_W/BASE_H` 各加 `BORDER*2`（370×409），坐标体系不变，上下留白均为 12px。测试断言同步为 370/409，并新增上下留白相等断言。15 规则 + 34 UI 全通过。
